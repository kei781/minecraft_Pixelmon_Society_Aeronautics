# Jade와 비행체 좌표 검증

실제 조립된 비행체에서 꺼진 레버를 조준하자 Jade 11.13.2가 월드 좌표 약 23과 저장 공간 좌표 약 20,481,037을 함께 사용했다. Sable의 큰 탐색 상자 보호가 요청을 중단했고, 클라이언트는 종료되지 않았다. 최초 오류와 당시 상태는 [기록](../evidence/jade-sublevel-raytrace-baseline.json)에 남겼다. 비행은 아직 검증하지 않았다.

호환 코드는 Jade의 계산용 hit 위치 읽기 다섯 곳을 월드 좌표로 투영한다. 반환하는 원래 hit 결과와 블록 위치는 유지한다. 내부 엔티티의 충돌 상자는 해당 비행체 좌표에서 contains/clip을 실행하고, 교차점은 월드 좌표로 돌려 거리 비교에 사용한다. 카메라와 기존 렌더 결과를 사용하는 동안 Sable의 렌더 pose 문맥을 설정하고 예외가 발생해도 finally에서 복원한다. 서버 블록 정보 요청은 두 정수 위치를 월드 좌표로 투영해 기존 거리 제한과 비교한다. 원래 거리 한계·로드 검사·엔티티 조건·큰 탐색 보호는 바꾸지 않는다.

일반 월드에서는 기존 contains/clip 호출과 서버 거리 계산을 그대로 호출한다. Jade가 없으면 두 선택적 대상 믹신은 적용되지 않는다. 고정 Jade 클래스에서 hit 위치 5곳, contains 1곳, clip 1곳, 서버 거리 1곳을 지정했다. 다른 버전에 추측으로 적용하지 않는다.

실제 Minecraft AABB와 Sable/JOML을 사용한 40개 기하 검사가 통과했다. 독립 소스 트리 두 곳에서 빌드·재난독화·ZIP 정규화한 결과도 동일하다. [빌드 기록](../evidence/jade-coordinate-candidate-build.json)의 런타임 상태는 별도로 구분한다. 기하 검사만으로 실제 조준과 서버 블록 정보 요청을 통과했다고 판단하지 않는다.

전체 354개 모드, 내장 JAR 75개, 클래스 79,468개를 검색했다. 최초 hit 위치 기반 검색 33개에 이어, Claude 지적에 따라 hit 읽기를 요구하지 않는 거리·contains·clip·엔티티 탐색 검색으로 넓혔다. SRG 메서드는 호출 소유자와 무관하게 찾아 클라이언트 플레이어·모드 하위 타입·MutableBlockPos도 포함한다. [확대 검색](../evidence/spatial-family-expanded-summary.json)은 클래스 1,340개를 후보로 찾았으며, Jade 전체 242개 클래스 중 5개가 해당한다. 확대 메서드 요약은 hit 읽기를 요구하지 않으며 인터페이스 호출도 센다. 이름이 보존된 MCP 거리 API는 Minecraft 소유자에 한정하므로 모드의 이름 기반 래퍼까지 상속 분석으로 증명하지는 않는다. 이 검색은 데이터 흐름이나 전체 모드 호환성의 증명이 아니다. 다른 모드의 거리·발사체·시점 계산은 해당 기능의 실제 회귀 검증을 계속해야 한다.

확대 검색으로 찾은 Jade 거리 표시도 기존 내부 hit를 그대로 받아 눈 위치와 직접 비교하므로 렌더 pose로 투영해 계산한다. 엔티티 서버 접근자는 이미 설정된 Sable의 Entity 거리 보정으로 이어진다. [위임 경로](../evidence/jade-entity-distance-delegation.json)를 확인했으며 같은 보정을 중복 적용하지 않는다. 실제 엔티티 데이터 응답은 별도 검증한다. 나머지 DatapackBlockManager는 한 BlockPos의 상자를 사용하므로 두 기준의 끝점을 섞는 원래 오류와 구분한다.

테스트 전용 Jade 관찰 도구는 실제 엔티티 탐색 호출이 반환한 뒤 입력 상자의 범위와 시작·끝 좌표를 기록한다. 서버에서는 원래 블록·엔티티 요청의 소비자에 같은 데이터를 전달하고 반환 횟수를 센다. 전달 반환과 클라이언트 수신 성공을 구분한다. 원래 호출·조건·데이터·반환값을 변경하지 않는다. 좌표 차이에 따른 진단 분류는 실제 프레임 조회의 증명과 구분한다. 이 JAR는 배포 팩에 포함하지 않는다.

관찰 도구 0.1은 `11.13.2` 의존성이 실제 `11.13.2+forge`와 달라 로딩 단계에서 거부됐다. [최초 실패](../evidence/jade-observer-first-launch-failure.json)를 보존했고 게임 검증으로 계산하지 않았다. 0.2는 정확한 버전을 지정하고 실제 Maven 버전 비교로 원래 범위 거부·새 범위 허용을 확인했다. 클라이언트 클래스도 전용 믹신으로 분리했다. N100 테스트 프로필은 운영 313개와 해시 고정 진단 2개만 허용하며, 관찰 파일이 없으면 검증을 거부한다.

0.2의 실제 N100 시작에서는 일반 실행 클래스가 Mixin 전용 패키지에 있어 로더가 거부했다. [로딩 실패](../evidence/jade-observer-server-loader-failure.json) 후 월드 309개 파일의 경로·내용 해시가 백업과 모두 같음을 확인했다. 0.3은 믹신만 `dev.psa.jadeprobe.mixin`에 두고 실행 클래스는 그 밖으로 옮겼다. 같은 문제가 있던 좌표 도우미도 `dev.psa.jademath`로 옮겼다. [전체 패키지 후보 검색과 음성 대조](../evidence/jade-mixin-namespace-family.json)는 이전 잘못된 두 파일을 검출하고, 현재 PSA 패키지에는 같은 일반 클래스가 없음을 확인한다. 기존 upstream 후보와 파싱하지 못한 설정 1개는 실제 결함이나 통과로 단정하지 않는다.

재빌드는 두 트리의 빌드 출력을 비운 뒤 클래스 경로 준비 작업과 전체 build/reobf를 차례로 실행했다. 바로 clean+build한 초기 실행은 Minecraft·Forge 상위 클래스 11개 누락으로 실패했고, 이를 성공으로 바꾸지 않았다. 별도 클래스 경로 준비 후 전체 컴파일과 정규화 결과가 일치했다. 데이터 생성 출력은 보존했다.

사용한 주입 API는 [MixinExtras의 공식 설명](https://github.com/LlamaLad7/MixinExtras/wiki/ModifyExpressionValue)에 따르며, 실제 포함된 0.4.1을 대상으로 빌드했다.
