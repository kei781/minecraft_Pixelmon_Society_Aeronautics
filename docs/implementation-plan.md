# 두 완료 목표와 phase 실행 계획

## 완료 목표

1. Windows 플레이어가 필요한 선행 프로그램을 설치한 뒤 하나의 패키지 가져오기/설치로 세 프로젝트의 같은 클라이언트를 준비할 수 있다. 패키지와 실제 사용할 안내가 있어야 한다.
2. N100 / Ubuntu / RAM 16 GB에서 Pixelmon + Society: Sunlit Valley + Create Aeronautics를 같은 서버·월드에 구성한다. 게임 기능과 최대 6인 부하를 실제로 검증한다.

두 목표는 모두 진행 중이다. 진단용 부분 조합이나 필수 파일이 없는 패키지를 최종 결과로 세지 않는다.

## 전역 제약

- 플레이어 계정은 각자 자신의 Microsoft 계정으로 로그인한다. 계정 정보나 SSH 설정·실제 서버 주소를 공개 저장소/외부 리뷰에 포함하지 않는다.
- 서버의 기존 월드·서비스를 덮어쓰지 않는다. 개발 검사는 새 전용 디렉터리와 구분된 시험 월드를 사용한다.
- 파일 다운로드, 코드/바이트코드 확인, 실제 실행, 오류 수정, 재실행을 반복한다. 새로 만든 호환 수정은 원본과 구분하고 출처·해시를 기록한다.
- 장애를 하나 찾으면 재현·원인 확인 뒤 같은 유형을 전체 모드에서 검색하고, 발견한 관련 항목을 회귀 검사한 다음 다른 유형의 장애로 넘어간다. 첫 증상만 숨기거나 예외 패킷을 버려 통과시키지 않는다.
- 사용자는 시험 세이브를 버려도 된다고 명시했다. 별도 폐기 가능한 QA 프로필에서 등록 아이템·블록·엔티티를 작은 묶음으로 검사한다. 데이터 왕복, 실제 소환, 클라이언트 표시, 설치·사용·상호작용, 세 프로젝트의 주요 플레이 동작은 각기 다른 검증 단계로 기록한다.
- 최초 개발 기반인 고정 Society `project-honey` / Minecraft 1.21.1 / NeoForge 21.1.262와 누락 파일 차단은 보존한다. 별도로 정식 Society 4.1.5A / Minecraft 1.20.1 / Forge 47.4.20 / 실제 Aeronautics 포팅 소스를 시험한다. 포팅본과 Pixelmon 구버전 베타의 차이 및 검증 한계를 기록한다.
- 원래 프로젝트를 조용히 빼거나 다른 프로젝트로 대체해 기동 성공을 만들지 않는다. 구현/이식이 필요하면 출처와 차이를 명확히 기록하고 해당 게임 기능을 검증한다.
- 상류 개발자 답변을 독립 작업의 전제 조건으로 두지 않는다. 사용자가 개발자 문의를 게시하지 않기로 명시했으므로 외부 문의를 게시하지 않는다.
- 각 phase는 구현·직접 검증·최신 안정 Claude Opus 독립 리뷰·지적 해소를 마쳐야 완료한다. 마지막에 전체 변경을 다시 리뷰한다.
- 리뷰는 작성자와 분리된 읽기 전용 소스 스냅샷으로 한다. 실제 테스트는 Codex가 실행한다. 판정 원문·대상 SHA·모델을 보존한다.
- 기본 브랜치 PR은 이 절차에서 병합하지 않는다. 검토 가능한 PR과 실제 설치 산출물을 별도로 관리한다.

## Phase 1 — 플레이어 패키지 경로

- Prism Launcher가 가져올 수 있는 `.mrpack` 내보내기와 Windows 안내를 구현한다.
- 공개 원본은 공식 URL·크기·해시를 패키지에 고정한다. 가져오기 도구가 원본을 내려받게 하고 계정/개인 설정을 패키징하지 않는다.
- 실제 N100 최소 조합과 짝이 맞는 진단 패키지로 형식과 실제 런처 가져오기를 먼저 검증한다. Society 미포함 진단용임을 파일명·화면 이름·메타데이터에서 구분한다.
- 전체 통합 내보내기는 필수 개발 파일·호환 패치 검증을 반드시 통과해야 한다. 필수 파일 누락 시 최종 패키지를 만들지 않는다.
- Windows 경로·중복 파일·해시·실패 시 산출물 보존과 실제 Prism 가져오기를 검증한다. macOS 가져오기 시험을 Windows 게임 실행으로 표현하지 않는다.
- 이 phase의 완료는 설치 도구/가져오기 경로의 준비이며, 세 프로젝트 최종 클라이언트 제공 완료는 아니다.

## Phase 2 — 필수 콘텐츠와 전체 기동

- Society 1.21.1 본체와 Sunrise Gardening의 실제 배포 파일/소스를 추가 추적한다. 공개 변경 이력과 파일 내부 메타데이터도 확인한다.
- 공개 소스 빌드나 필요한 이식을 검토하고, 원본 또는 파생본의 정체성·기능을 확인한다. 이름/블록만 채운 가짜 파일로 검사를 통과시키지 않는다.
- 전체 팩의 레지스트리·KubeJS·클라이언트/서버 모드 의존성과 충돌을 실행으로 해결한다.
- 실제 전체 월드 기동이 이 phase의 완료 조건이다.

## Phase 3 — N100 통합 서버와 대응 클라이언트 준비

- 전체 검증한 입력으로 새 전용 서버 디렉터리와 재실행 가능한 시작/정지 경로를 구성한다.
- 접속 검사에 쓸 전체 플레이어 패키지를 먼저 만든다. 서버와 공통 모드·설정을 맞추고 설치 가져오기 및 서버 저장·재시작을 확인한다.
- 실제 Windows 접속과 게임 기능 검증은 준비한 패키지를 사용해 다음 phase에서 이어간다.

## Phase 4 — 최종 배포와 부하 검증

- 전체 세 프로젝트 패키지와 플레이어 설치 안내를 최종 산출물과 일치시키고 실제 Windows 로그인/접속을 확인한다.
- Pixelmon 포획/전투, Society 농사/경제/진행, Aeronautics 조립/비행을 실제로 확인한다.
- N100의 최대 6인 부하를 검증한다. 실제 접속/합성 부하의 범위를 구분하고 성능 수치를 과장하지 않는다.
- 모든 이전 지적·인터페이스·누락 요구를 대상으로 Claude 최종 리뷰를 진행한다.
- 두 완료 목표를 모두 충족했을 때만 전체 작업을 완료 처리한다.

실행 중 발견한 UI 하위 작업(Task 5): Society FancyMenu와 Pixelmon 일시정지 메뉴의 중복 링크를 클라이언트 전용 패치로 보정한다. 실제 전체 클라이언트에서 GUI 배율 2·3·4의 겹침과 보존할 버튼을 비교하고, v6 이용자용 작은 JAR 및 v7 통합 가져오기 파일을 준비한다. 원본 설정을 변경한 경우에는 보정을 적용하지 않으며, N100의 서버·월드는 변경하지 않는다. 독립 리뷰 뒤 전달하고 Windows에서 재확인한다.

실행 중 발견한 동기화 하위 작업(Task 6): 실제 Windows 접속의 플레이어 필드 22 오류를 양쪽 필드 배정과 초기화 순서 대조로 재현한다. 전체 공통·클라이언트 모드의 동기화 필드 등록 호출을 검색해 같은 유형을 조사하고, 추가 발견된 광산수레 등록 대상 문제도 양방향 대조 검사한다. 계정 인증·OP·네트워크 패킷 값을 변경하지 않고 기존 모드의 등록 순서/대상만 보정한다. 전체 목록을 수집하는 시험 모드는 최종 이용자 팩에서 제외한다. 기존 N100 월드를 백업·보존하고 새 QA 프로필에서 인증 접속과 재접속을 검증한다. 최신 안정 Claude Opus 독립 리뷰를 마친 뒤 다음 콘텐츠 검사 작업으로 진행한다.
# Task 10: Jade와 비행체 좌표 오류

실제 조립된 비행체의 레버 조준에서 재현된 Jade 탐색 상자 오류를 먼저 수정한다. 전체 모드의 유사 호출을 검색하고, 클라이언트 탐색·충돌점·서버 거리 계산을 같은 좌표 기준으로 맞춘다. 기존 보호와 거리 제한을 유지한다. 독립 빌드·기하 검사·실제 Windows 재현 위치 회귀·Claude 독립 리뷰를 거쳐 비행 검증을 재개한다. Task9 전체 렌더 탐색, 6명 부하, 최종 통합 리뷰와 사용자 목표 두 개는 계속 미완료다.

## Task 11: 원본 아이템 모델 리소스 누락

Task9의 실제 인증 렌더 검사에서 `decorative_blocks:blockstate_copy_item`이 기본 누락 모델로 확인됐다. 같은 모드 53개 아이템과 전체 17,239개 등록 아이템의 리소스 경로를 대조하고, 동적 모델과 실제 누락을 구분하는 클라이언트 자동 조회 진단을 추가한다. 원본 도구 모델·텍스처를 참조하는 이름 연결만 플레이어 내보내기에 추가하며, 고정 원본 해시와 기존 리소스 충돌을 검사한다. 원래 KubeJS 서버/클라이언트 동일성 검사는 유지하고 추가 에셋은 클라이언트에만 둔다. 맥에서 수정 전후 실제 모델 조회·관련 렌더 회귀를 검증한다. Windows는 사용자가 꺼둔 상태이며, 최종 Windows 가져오기 검증은 재개 시 진행한다. 현재는 후보 수정이며 두 목표 완료를 뜻하지 않는다.

## Task 12: 원래 블록 모델이 있는 다섯 아이템 보정

Task11 수정·진단 도구는 Claude R3에서 소스 검토를 통과했고 Decorative Blocks 53개 실제 렌더 회귀를 통과했다. 남은 21개도 각각 실제 드롭 렌더 누락을 확인했다. 이 중 DisplayDelight의 수프·스튜 세 개, VerdantVibes 화분, VintageDelight 식초병은 원본의 대응 블록 모델이 있어 이를 참조하는 클라이언트 에셋을 추가한다. 원본 JAR과 참조 리소스 해시·충돌 가드를 유지하고 전체 조회 및 관련 네임스페이스의 실제 렌더를 다시 확인한다. 나머지 16개와 손·인벤토리 화면, 설치·사용, 최종 Windows 가져오기, 6인 부하와 두 전체 목표는 미완료다.
