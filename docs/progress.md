## 최신 상태 — 2026-11-10

전체 단계는 **설치물 제작·통합 구동 완료 → 안정화와 최종 검수 진행 중**이다.
최신 [v16 패키지](../evidence/player-pack-v16-candidate.json)는 약 1.14GB이며
[Windows 안내](windows-client.md)에 따라 가져온다. N100의 새 접속용 서버는
런타임·라이브러리도 독립 복사했고 기존 QA 월드는 정상 정지해 보존했다.
최신 Mac 인증 입장은 기존 SSH의 루프백 전달로 확인했다. 직접 LAN 경로의
`NoRouteToHost`는 남아 있다. 1명 상태의 TPS 20·평균 tick 14.289ms를
6인 성능으로 환산하지 않는다. [실제 배치·접속 기록](../evidence/n100-v16-player-deployment.json).

이전 QA에서는 실제 Pixelmon 포획·턴 전투, Society 생존 농사·출하 정산,
Aeronautics 조립·생존 수직 비행·착륙을 확인했다. 최신 v16에서 이 모든 동작을
다시 검증한 것은 아니다. 모든 아이템의 서버 소환·정리와 클라이언트 모델 조회는
실제 렌더·사용 검증과 구분한다.

Task 11~13의 후속 코드·원본 모델 연결·네이티브 전투 진단은 각각
[Task 11 기록](../evidence/minecraft-qa-control-build-and-runtime.json),
[Task 13 수락](../evidence/task13-review-acceptance.json) 및 개별 문서에 보존했다.
Task 14는 누케닌 다이맥스 최대 HP 보정과 코드로 수행하는 접속 검증을 수락했다.
원본 22개 수치 검사 중 6개 실패 → 수정 후 22개 통과, HP 1인 잉어킹 두 대조는
수정 전후 모두 최대 HP 2를 유지했다. 기존 전체 313개 모드의 20개 대조도 통과했고,
최신 공통 JAR는 그때와 동일하다. 실제 전투 전체 통과를 뜻하지는 않는다.
[종 조건 대조](../evidence/pixelmon-dynamax-hp-species-guard-regression.json).

[PR #11](https://github.com/kei781/minecraft_Pixelmon_Society_Aeronautics/pull/11)의

R2 CLEAN, [PR #12](https://github.com/kei781/minecraft_Pixelmon_Society_Aeronautics/pull/12)

남은 항목은 춤 기술/셸트랩 간헐 실패의 원인 및 실제 교체 경로,
모델 누락 16개와 넓은 실제 렌더·사용 검사, 전체 데이터팩 갱신 오류·ReliableEmi
그룹 오류 11건, 생존 포획 세부 조건·수평 비행·장시간·실제 6인 부하,
최신 Windows 신규 설치와 최종 통합 리뷰다. 두 사용자 목표는 최종 완료로 표시하지 않는다.

이전 검증: N100에서 Pixelmon/Create/Aeronautics/Sable 최소 조합이 기동하고 물리 엔진 초기화와 엔티티 검사를 통과했다. 전체 Society는 포함하지 않았다. 해당 호환 코드 `12f9a56`은 Claude Opus 5.5 독립 리뷰에서 CLEAN이었다.

## Phase 2 — 실제 콘텐츠/전체 월드 기동 완료

`society-2.0-1.21.1.jar`와 `sunrisegardening-1.0.jar`는 아직 없다. 전체 staging/export는 계속 차단하며 가짜 모드·다른 프로젝트로 누락을 숨기지 않는다. Orchard와 Plentiful Ponds 소스 후보 두 개는 확보했다.

요청한 REA 6.8.0을 작업 폴더에서 실제 실행했다. 공개 Society 1.22 JAR의 ZIP 목록 분석은 성공했지만 auto 심층 분석은 `capability_unavailable/unsupported_provider`로 종료했다. Java 분석은 기존 CFR·javap 경로가 가능하다. [REA 결과](rea-findings.md)에 실제 범위와 추가 소스 계보 조사를 남겼다.

사용자는 개발자에게 문의를 게시하지 않기로 명시했다. 외부 문의는 게시하지 않았다. 사용자가 파일을 설치해 확보하는 경로와 공개 파일/소스 조사를 이어간다. 필수 두 파일을 확보하면 해시와 정체성을 확인하고 전체 기동 검증을 재개한다.

별도 1.20.1 후보: 정식 Society 4.1.5A 서버팩 원본 311개 모드를 유지하고 Pixelmon 9.2.3 베타 및 실제 Aeronautics Forge 포팅 소스를 더해 전체 월드가 시작됐다. 데이터/아트 누락과 Leaves Be Gone의 조립 충돌을 수정했다. 수정본에서 퀘스트 1,142개, 정상 몹 공존, 필수 물리 태그, 실제 1블록 구조물 조립 및 명령 권한 검사를 확인했다. 게임 플레이·Windows·N100 전체 팩·6인 검증은 남아 있다. [후보 상세](forge-candidate.md). Phase 2 Claude R1은 P2(공식 입력 근거)와 P3(리소스 생성 순서)를 지적했다. R2에서 이전 두 건은 해소됐고, 빈 해시 차단 검사와 최초 JAR/정규화 JAR 연결 기록 P3 두 건을 추가로 수정했다. 27개 검사와 실제 저장 큐 복원까지 통과했으며 R3 재리뷰 전이다.

Phase 2 완료 범위: 별도 Forge 후보의 실제 전체 월드 기동과 호환 도구 검증. BASE `5709d84`, 구현 `65600fb`, 수정 `2c2a82a`·`7b8876d`. 최신 Claude Opus 5.5 세 회차, R3 CLEAN. 브리지 적용 후 실제 PR 미해결 스레드 0건. 컨트롤러 검사 27개, 깨끗한 소스 재빌드/정규화 해시 재현, 실제 조립·몹 공존·저장 월드 재시작·FULL 청크 틱 큐 보존을 확인했다. 원본 기동 JAR `5ac3cda9…`와 배치용 정규화 JAR `0f7d5724…`의 연결도 실제 변환으로 검증했다. 두 최종 목표는 여전히 진행 중이다.

Phase 3은 N100 전체 서버 배치와 같은 공통 모드를 쓰는 플레이어 패키지를 준비한다. 실제 Windows 로그인/접속·게임 기능·6인 검증은 준비된 패키지로 이어서 수행한다.

## Phase 3 — N100 배치와 전체 클라이언트 준비 검증 완료

N100 새 전용 폴더에 Corretto 17과 Forge 47.4.20 및 전체 JAR 313개를 설치했다. 시험 월드의 몹 공존·물리 조립·저장·정지·재시작을 통과했고 시험 월드를 보존한 별도 플레이어 월드가 실행 중이다. TCP 상태 핑으로 프로토콜 763, 최대 6명/현재 0명, Forge 메타데이터를 확인했다. 실제 주소는 공개하지 않는다.

전체 클라이언트 v4는 약 1.14 GB다. JAR 353개, CF 리소스팩 15개·셰이더 1개와 원본 overrides를 포함한다. 실제 macOS Prism 11.1.1 가져오기 후 파일 7,923개 SHA256을 대조했다. v1의 리소스 ZIP 오배치를 수정했으며 현재 mods에는 ZIP이 없다. v3는 포팅본의 카메라 API에 맞춰 클라이언트 전용 Shoulder Surfing 5.0.4를 사용한다. 서버 공통 모드 311개는 그대로다.

공식 데모 실행으로 v3의 렌더러 `VerifyError`를 실제 재현했고, 변환된 클래스에서 원인이 된 지역 변수 슬롯 덮어쓰기를 확인했다. 단일 인수 래퍼로 수정한 뒤 Pixelmon의 없는 Realms 버튼 참조도 재현해 클라이언트 전용 메뉴 가드를 추가했다. v4와 같은 모드 JAR의 검사 인스턴스가 두 종료 지점을 통과했고 5분 이상 살아 있음을 확인했다. UI 도구가 Java 게임 창을 선택하지 못해 화면을 직접 확인하지는 못했다. 실제 인증 접속·Windows·게임 플레이 성공으로 간주하지 않는다.

컨트롤러 검사 41개를 실제 N100 Ubuntu에서 모두 통과했다. macOS에서는 39개 통과, Linux 전용 2개 제외다. 핵심 내보내기 성공·실패 경로 픽스처 8개를 포함하며 픽스처를 게임 모드로 실행하지 않는다. 실제 공식 입력으로 `--mode player` staging의 바인딩·별도 월드·EULA 미동의도 확인했다.

Phase 3 첫 독립 리뷰 실행은 출력의 줄 위치가 diff 검증을 통과하지 못해 거부됐다. 판정을 채택하거나 GitHub에 게시하지 않았으며 원문을 보존했다. 새 커밋 기준으로 전체 phase 리뷰를 다시 수행한다. 최종 Windows 게임/6인 검증도 아직 남아 있다.

Phase 3 R2는 실제 최신 Claude Opus 5.5로 `35959ca`를 검토했다. P1·P2 없이 P3 두 건(동시 시작의 로그 이동 경쟁, 보존 문서의 v2 표기)을 게시했고 수정했다. N100 회귀 검사 42개 모두 통과, macOS 39개 통과·Linux 전용 3개 제외다. 실행 중인 실제 서버에서도 동시 시작 후 로그 inode가 유지됐다. 고정 원본에서 두 패치를 순서대로 적용한 새 빌드는 38초/13개 작업 실행으로 성공했고 배치용 JAR 해시도 동일했다. 작성자가 스레드를 해소하지 않았으며 R3 재리뷰 전이다.


Phase 3 완료 범위는 전체 플레이어 팩 준비와 N100 배치·기동 검증이다. BASE `c710244`, 최종 코드 `15a4983`. 최신 Claude Opus 5.5 R3가 두 스레드 모두 해소/CLEAN으로 판정했고 브리지 적용 후 실제 미해결 수는 0건이다. CI 체크는 설정돼 있지 않으며 컨트롤러 직접 검사와 구분한다. 추가 Linux 제어 검사 20회/60건을 통과했고 잠금을 제거한 임시 복사본에서는 기대한 회귀 실패를 확인했다. 실제 N100 Java의 잠금 FD도 없었다(그 프로세스는 제어 스크립트 갱신 전 시작됐다는 범위도 기록한다).

Phase 3 당시 산출물은 v4이며 이전 v1~v3 대신 사용하도록 안내했다. Phase 4의 Windows 정품 로그인/접속, 포획·전투, Society 진행, 조종 비행과 실제 6인 검증은 남아 있다. 현재 제어 가능한 Windows 인증 세션과 6명 플레이어가 없으므로 데모 초기화·상태 핑을 해당 검증의 성공으로 바꾸지 않는다. 모든 최종 목표의 완료 상태는 아직 아니다. [Phase 3 판정 기록](../evidence/phase3-acceptance.json).
